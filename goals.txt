ContainerConnect - Project Goals
================================

Goal
----
Build a developer-friendly CLI for quickly debugging and interacting with
containerized workloads running on AWS ECS and EKS.

The core idea:

    "I want to debug this service."

rather than:

    "I need to find the task ARN, container name, and construct an
     ECS ExecuteCommand invocation."

PHASE 2 - ECS EXEC
--------------------------------------------------

[ ] Create "cc ecs exec" command

Target usage:

    cc ecs exec --cluster <cluster> --service <service>

The command should:

[ ] Resolve the requested service
[ ] Verify the service exists
[ ] Verify ECS Exec is enabled
[ ] Find RUNNING tasks belonging to the service
[ ] Automatically select a suitable task
[ ] Identify the application container
[ ] Handle services with multiple containers
[ ] Determine an appropriate shell
[ ] Call ECS ExecuteCommand
[ ] Establish the SSM session
[ ] Launch the local Session Manager plugin
[ ] Provide an interactive shell inside the container

--------------------------------------------------
PHASE 3 - MAKE EXEC SMART
--------------------------------------------------

[ ] Automatically select a healthy RUNNING task
[ ] Allow explicit task selection when required
[ ] Automatically identify the primary application container
[ ] Allow --container override
[ ] Automatically detect /bin/bash vs /bin/sh
[ ] Give useful errors when a shell is unavailable
[ ] Give useful errors when ECS Exec is disabled
[ ] Give useful errors when no tasks are running

Example:

    cc ecs exec --cluster production --service payments

Should hide all of the following from the user:

    cluster
    task ARN
    container name
    task definition revision
    ECS Exec configuration
    SSM session details

--------------------------------------------------
IMPORTANT DESIGN PRINCIPLE
--------------------------------------------------

Do not build features just because they are technically possible.

The goal is to reduce the number of things a developer has to think about
when debugging a running container.

Prefer:

    cc ecs debug payments

over:

    aws ecs list-tasks ...
    aws ecs describe-tasks ...
    aws ecs execute-command ...
    ...

ContainerConnect should handle the infrastructure details and expose
a simple developer-oriented workflow.
